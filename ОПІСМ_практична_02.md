### 3.1. Завершення рядків

Протокол вимагає, щоб кожен рядок повідомлення завершувався послідовністю з двох символів — повернення каретки та переведення рядка (позначається `CRLF`, `\r\n`). Термінал за натискання клавіші Enter надсилає лише переведення рядка (`\n`). Частина серверів таке відхилення допускає, частина — ні.

Для інтерактивного введення використовують утиліту `nc` з ключем `-C`, який замінює одиночне переведення рядка на `CRLF`:

```
nc -C <домен> 80
```

Перевірити версію утиліти: `nc -h`. Якщо встановлено варіант `ncat` (пакет `nmap`), відповідний ключ має назву `--crlf`.

Якщо запит не дає відповіді або дає код `400`, першою гіпотезою слід перевіряти саме завершення рядків.

### 3.2. Особливості Windows

Утиліта `nc` до складу Windows не входить. Для виконання частини A без переходу в Killercoda використовують засоби PowerShell згідно з **Додатком Г**.

Команда `curl` у PowerShell є псевдонімом командлета `Invoke-WebRequest`, який має інший набір параметрів. Її слід викликати як `curl.exe`.

| Дія | Linux / macOS | Windows |
|---|---|---|
| Запит із діагностикою | `curl -v <URL>` | `curl.exe -v <URL>` |
| Сире з'єднання | `nc -C <домен> 80` | див. Додаток Г |
| З'єднання із захистом | `openssl s_client ...` | `openssl.exe s_client ...` |

## ДОДАТОК Г. Виконання частини A засобами Windows PowerShell
Наведені команди замінюють утиліту `nc` у завданнях A.1–A.4. Кожен блок виконують цілком.

**Завдання A.1** (запит формується у змінній; інтерактивне введення засобами PowerShell не відтворюється):

```powershell
$d = "<домен>"
$c = New-Object System.Net.Sockets.TcpClient($d, 80)
$s = $c.GetStream()
$w = New-Object System.IO.StreamWriter($s)
$w.Write("GET / HTTP/1.1`r`nHost: $d`r`nConnection: close`r`n`r`n")
$w.Flush()
(New-Object System.IO.StreamReader($s)).ReadToEnd()
$c.Close()
```

**Завдання A.2** — той самий блок, у якому рядок `$w.Write(...)` замінено на:

```powershell
$w.Write("GET / HTTP/1.1`r`nConnection: close`r`n`r`n")
```

**Завдання A.3.1** — той самий блок зі зміненим рядком `$w.Write(...)`:

```powershell
$w.Write("GET / HTTP/1.1`r`nHost: <чужий-домен>`r`nConnection: close`r`n`r`n")
```

**Завдання A.3.2:**

```powershell
$w.Write("GET / HTTP/1.1`r`nHost: opism-pr02.invalid`r`nConnection: close`r`n`r`n")
```

**Завдання A.3.3:**

```powershell
$w.Write("GET / HTTP/1.0`r`n`r`n")
```

**Завдання A.4:**

```powershell
$w.Write("GET /opism-pr02-12345 HTTP/1.1`r`nHost: $d`r`n`r`nGET / HTTP/1.1`r`nHost: $d`r`nConnection: close`r`n`r`n")
```

Зворотна коса риска перед символами `r` та `n` у PowerShell не використовується; послідовність `` `r`n `` (зі зворотним апострофом) позначає ті самі два службові символи, що й `\r\n` у команді `printf`.
